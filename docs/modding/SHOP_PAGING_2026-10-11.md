# 单位商店翻页与新增单位（2026-10-11，核心 r47、r48）

## 1. 现象与原因

玩家报告：在 SHOP 购买单位时“点下一个，界面刷出后立即点上一个”游戏崩溃，翻页后反复落入新增社区单位所在的页。

单位商店（模式 2）每页至多 50 件商品，页首为 BACK 卡、页末为 NEXT 卡。社区商品追加在原版 259 项目录之后（扩展目录，社区头部 +44，长度 +48）。原生翻页代码按原版目录编写，存在以下问题：

| 编号 | 位置 | 问题 | 出现条件 |
| --- | --- | --- | --- |
| 1 | `UpdateSelectedMenuShop` BACK 回溯（0x1020c3e6） | 读原版 259 项目录；页首在社区段时读到目录之后的数据，上一页起点算错，读到无效商品编号时崩溃 | 页首位于社区商品段 |
| 2 | `InitMenuShopWindowOnlyOneTask`（0x10209a04） | 单卡重建同样读原版目录 | 同上（该函数在 1.46.0 中没有直接调用者） |
| 3 | `SC_MenuShopInit` 商品总数 | 写为 259 + 社区槽位数，含内部子单位与通关奖励等不进商店的槽位 | 一直存在 |
| 4 | BACK 回溯的计数规则 | 只数“启用且未售罄”的商品，不考虑 FILTER；正向建页会跳过被筛选隐藏的单位，BACK 每次只退回 50 个目录项 | 开启 FILTER 且筛选后超过一页 |
| 5 | NEXT / BACK 卡的存在判定 | 同样不考虑 FILTER；本页恰好排满、之后只剩被隐藏的商品时仍显示 NEXT，进入空页；空页上选中序号为 −1，BACK 读取 BACK 卡自身的字段作为目录序号 | 同上 |

问题 4、5 在原版中也存在。原版商店不足 260 件，筛选后很少超过一页，因此没有表现出来；单位增多后会实际出现。

## 2. 修复

- r47（`src/community_blocks.inc`）：问题 1、2 改读扩展目录；问题 3 改用加载器写入的实际目录长度。
- r48（`src/community_blocks.inc`，`src/lab_hooks.cpp` 导出 `msd_guest_call`）：新增 `shop_visible`。它按正向建页（`InitMenuShopWindowTask`）对各商品类型的同一判定决定是否显示：
  - 单位：所属阵营未被筛选隐藏、启用、未售罄；
  - 组合包：启用、未售罄，且包内单位均未被隐藏；
  - 类型 0/7：启用且未售罄；
  - 类型 3：只在模式 6 显示；
  - 其余类型：直接显示。

  该判定用于以下四处：
  - BACK：从当前页实际起点向前数 50 件显示的商品，与 NEXT 互逆；
  - BACK 卡：起点之前存在显示的商品时才建立；
  - NEXT 卡：之后存在显示的商品时才建立（钩子位于循环体 0x1020be02，因为生成代码在 0x1020bdd8 块内联了首次循环判定）；
  - 建页入口：起点之后已无显示的商品时显示最后一页，不建立空页。

  活动商店（`event_trial_hooks.cpp` 的独立目录）与其他商店模式保持原有路径。

## 3. 以后新增单位或模组单位

- 扩展目录由 `community_content.py` 在启动时按全部可售的本体与模组单位及组合包生成，翻页代码只读这份目录及其长度，新增单位无需修改翻页代码。
- 显示判定调用原生函数（`IsMenuShopEnable`、`IsMenuShopSoldOut`、`GetUnitAffiliation` 等），社区与活动的钩子照常生效，新单位的开放条件、所属与价格自动参与判定。
- “单位（强化）”列表与编队列表按预先建好的紧凑列表以固定 50 件翻页（BACK 为起点 −50），不做回溯计数；其列表容量已于 M1b 按实际数量处理（`docs/modding/M1B_ICON_PAGES_AND_SCALE_2026-10-10.md`）。

## 4. 验证（`verification/shop_flip_crash_20261011/`，隔离存档，SHA-256 由验证入口拦截）

- 初始进度存档：逐页 NEXT → 立即 BACK → NEXT 与从社区段建页（起点 260/265/270）后 BACK，r46 在社区段 BACK 时崩溃，r47、r48 均正确。
- 500 个测试单位（`fixtures/content_500`，目录 776 项）：
  - 不筛选，NEXT 14 页、BACK 13 页，r47、r48 均与正向页序互逆；
  - 只显示一个阵营：r47 的 BACK 分别用了 11、14 步，页面重叠；r48 与正向页序互逆；
  - 恰好排满三页、之后只剩被隐藏的商品：r47 进入空页，空页上 BACK 跳到无关页面；r48 不显示 NEXT 卡，BACK 正确；
  - 在最后一页实际购买最后一件显示的单位：勋章扣除，卡片显示“已購買”，BACK 回到上一页。
- 回归：活动勋章商店 20 项、普通商店 UNIT 页（r47 与 r48 相同）、VS CPU 21 项。

r48 第一版的一次不筛选运行在 BACK 阶段停止推进（进程无 CPU 占用）。此后修订版加入卡顿时输出调用栈的看门狗，同一用例未再出现，原因未确定。
