# 本地双人对战设计记录（2026-10-06，商讨阶段，未实施）

本文记录本地双人对战（同一台机器，P1 对 P2）的已确认决定与待定事项。当前仅作设计留档；实施排在连线对战与额外关卡之后，开工时再细化。依据为 LAB 现有实现（`docs/lab/HANDOFF_LAB_UI.md` 第 2.1、2.2 节）。

## 1. 可复用的 LAB 基础
- 战斗底座：绕过 Wi-Fi 菜单建立 GameMode 1 的 1v1 战斗，对手为 `BattleControllerNetPlayer`（PlayerBase 系，具备 AP、10 槽、出兵、绝招、弹头车、据点升级），无网络收发。
- 双方 HP 本地对称结算（清除 +981 远端同步标记）。
- 底栏左右分栏（钩子版本 3）：两侧各自的牌组、AP、冷却、AP 升级与弹头车状态，各自滚动；敌方 AP 数值框、人物动画与朝向独立。
- 敌方操作的原生调用路径：`createUnit`（vtable+0x94）、`actionUnitSpAttack`（+0x98）、`actionMetasuraHou`（+0xa0）、`actionKyotenLevelup`（+0xa8）。

## 2. 已确认的决定
| 事项 | 决定 |
| --- | --- |
| 镜头 | 仅 P1 控制，操作逻辑与原版相同；P2 无镜头控制（用户确认接受这一不对等）。 |
| P2 可选单位 | 完全来自 P1 存档中已拥有的单位。 |
| 键盘＋鼠标布局 | 采用下表方案。 |
| 控制器（手柄）布局 | 需另行设计，键盘方案不直接套用；待定。 |
| 完全控制 | 对战中关闭（正常 AP 增长与冷却）；双方 AI 关闭。 |

### 2.1 键盘＋鼠标布局（方案）
| 操作 | P1 | P2 |
| --- | --- | --- |
| 查看与选择单位 | 鼠标拖动左半区出兵栏滚动 | ←/→ 移动选中格，右半区自动滚动到选中格 |
| 出兵 | 鼠标点击格子；或 1–0 | ↑ 出兵选中格 |
| AP 升级 | 鼠标点击；或 ` | ↓ |
| 弹头车 | 鼠标点击；或 - | 另配一键（待定，建议右 Shift） |
| 绝招 | 点击己方单位；或 Space | 另配一键（待定，建议右 Ctrl，发动全部就绪单位） |
| 镜头 | 鼠标拖动战场 | 无 |

- P2 选中格高亮复用原生“按下格”显示：把敌方出兵栏状态的按下格（头部 +0x70 区的 operator+32 对应字）设为选中格，由原生绘制。
- 键位应分散布置，降低多键同时按下时的键盘串键风险。

## 3. 相对 LAB 需要新增或改变的部分
1. 入口：独立菜单项或启动入口；默认关闭完全控制与双方 AI；P2 牌组从 P1 存档已拥有单位中选择（以后接 LAB 准备界面 T8）。
2. 输入隔离：对战中鼠标只作用于 P1。停用“点击战场敌方单位发动其绝招”（T1）以及鼠标对右半区底栏的点击。
3. P2 选择光标：←/→ 选格、自动滚动、↑ 出兵；高亮见 2.1。
4. 结算：战斗结束显示 P1 胜 / P2 胜，返回入口；不进入 Wi-Fi 结算。
5. 存档与奖励：须先完成 LAB T9（拦截结算奖励与 `WriteMainSaveData`）；对战不得写入玩家存档，不能依赖测试存档副本兜底。
6. 暂停：GameMode 1 中原生暂停不可用，需先完成 LAB T6（战斗中菜单）。
