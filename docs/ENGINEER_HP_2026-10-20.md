# 修筑类单位（工兵）的生命与受击（2026-10-20，核心 r71）

## 1. 用户设定

- 工兵的生命按其修筑对象的生命（随等级）的 5% 计算，不再固定为原生的 1；计算结果不足 300 时取 300（下限，各等级均适用）。
- 需要开关：一般情况按生命计算；部分单位以后会单独设为“一击即跑”（原生行为），不得把行为写死。

## 2. 原生机制（静态反汇编 1.46.0）

- `BattleAction_Kouhei::damageAction`（0x16d772）每次受击都预约状态 100（撤退），与剩余生命无关。原生工兵生命为 1，因此“挨一下打就撤退”。只提高生命不能改变该行为。
- `BattleUnit::damage`（0x1e0a4c）在调用动作类的 `damageAction` 之前已扣血；生命归零时通知击毁（给予击毁 AP），并设身体状态 4。
- 状态 100 / 110 / 120 播放动作 12 并 `childRemoveAll`（未完成的修筑对象被移除），随后进入状态 142 走回己方据点后消失；动作类没有状态 80（击退）的处理。
- 修筑对象为状态 +0xa0（字 40）：`BattleAction_Kouhei::update` 状态 50 以 `getStatus(39)` 调用 `createChildObject`（`getStatus` 的编号 n 对应字 n+1，如生命为编号 2、字 3）。字 39 为召唤间隔，与修筑对象无关。
- 迫击炮兵类（163、171 与正规军迫击炮兵 1036，`Mortar_Kouhei` / `GuerrillaMortar_Kouhei`）使用默认受击处理且没有状态 80 的处理，提高生命后会因击退停在状态 80，本次不在范围内。

## 3. 实现

- 核心 r71（`src/community_content.cpp`、`src/community_blocks.inc`，导出 `msd_community_engineer_hp_version() == 1`）：
  - 社区头部 +176 为按生命计算的单位表（每项 UnitID、百分比、下限），+180 为项数；不在表中的单位保持原生。
  - 生命：`BattleInfo::getUnitStatus` 的尾部（既有倍率处理之后）对表中单位以嵌套调用取修筑对象同等级的状态，生命 = max(下限, 修筑对象生命 × 百分比 / 100)。修筑对象的生命含其自身的倍率（例如 MKII 箱体 1042 的 [20,9]）。
  - 受击：钩取 `BattleAction_Kouhei::damageAction`。表中单位扣血后生命仍大于 0 时只播放受击闪光（同 `BattleObject::playHitEffect` 0x1de114），继续行进或修筑；生命耗尽时按原生撤退（动作 12、移除未完成的修筑对象、走回据点）。
- 宿主（`community_content.py` 及 `src/` 镜像）：
  - `community_content/content.json` 的 `engineer_hp` 为缺省方式与原版 UnitID 的单独设定：`{"mode": "hp", "percent": 5, "minimum": 300, "units": {"<UnitID>": {...}}}`。`mode` 为 `"hp"`（按生命计算）或 `"hit_and_run"`（一击即跑，原生）；`percent` 1–100，`minimum` 1–1000000。
  - 单位文件（本体与模组）可写同格式的 `engineer_hp`（不含 `units`）；单独设定可只写 `percent` / `minimum`，方式沿用缺省。
  - 只适用于动作类为 `BattleAction_Kouhei` 的单位（原版 24 个，社区单位按 `base_id`）；对其他单位写此设定时拒绝载入。未写 `engineer_hp` 的内容目录保持原生。
  - 例：把沙包工兵设为一击即跑：`"units": {"5": {"mode": "hit_and_run"}}`；把木乃伊召唤箱 MKII 设为一击即跑：在其单位文件写 `"engineer_hp": {"mode": "hit_and_run"}`。
- 范围：敌我双方相同，关卡中由敌方放出的工兵同样适用。

## 5. 验证（隔离存档，核心 r71，未计算 SHA-256）

- 状态读取（`verification/pvz_zombies_20261012/probe_engineer_status.py`）：沙包 300 / 300、金屬要塞 300 / 750、巨型約翰 1000 / 2000、MKII 300 / 500；迫击炮兵 163 仍为 1。
- 开关（`verification/engineer_hp_20261020/content_mixed`）：沙包设为一击即跑、MKII 单位文件设为一击即跑后生命均为 1；巨型約翰单独设 10%、下限 500 后为 2000 / 4000；对非修筑类单位（UnitID 2）写设定时拒绝载入。
- LAB 战斗（`driver_battle.py`，敌方马可与步枪兵 Lv1 远程攻击）：沙包工兵修筑中受击 300 → 160，继续修筑并建成沙包，之后按原生走回据点；敌方一侧的工兵结果相同。Lv1 工兵被 Lv40 马可一击打空生命后按原生撤退（动作 12 → 14、状态 142）。
- 一击即跑与原生相同：同一场景在一击即跑设定下，r71 与 r70 的 500 帧双方单位记录逐帧相同（受击后生命 0、状态 100、未完成的沙包被移除）。
- 回归：不含工兵的战斗（`fix4_bite`，900 帧）r70 与 r71 逐帧相同；回滚确定性（`n1_engineer_wrapper.py`，编队含沙包、金屬要塞、MKII、巨型約翰与 Lv1 沙包，按概率 0.3 每帧随机回滚 1–8 帧）1702 帧与参照逐帧一致。
- 未覆盖：实体窗口手动操作、联机两机、各关卡平衡；修筑对象生命变化后工兵生命的显示（单位强化 / 商店 STATUS 仍显示修筑对象的生命，第 154 节）。
