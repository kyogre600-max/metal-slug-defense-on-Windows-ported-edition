# IRON SENTINEL（钢铁哨兵）按 MSA 原始数据重做的方案

日期：2026-10-21（Asia/Shanghai）。状态：方案待用户确认；游戏代码、内容、核心与运行目录未改动。前一版（R4，AGENTS 第 176 节）以 `disabled_units` 停用。

## 1. 依据

### 1.1 MSA 中的单位

- MSA 7.13.0（arm64 `libAppMain.so`，build-id `9acaace5…`）中钢铁哨兵为 UnitID 287（第一形态，动作类 `BattleAction_IronSlider`，开放）与 UnitID 288（第二形态，`BattleAction_IronSlider_2`，开放时间 2030-12-31，即只由 287 召唤）。两者共用同一动作记录（0x49fda20）。
- 记录内容：图集 `iron_slider_out.obm`（2048×1024，PALETTE8 RGBA5551）与 `ironiso_1_out.obm`（256×256，同格式）；矩形 318、帧 319、受击框 2、攻击框 11、脚本 142。
- 导出位置：`F:\egg\research\metal_slug_attack\decoded\units\0287\`（`record.json`、两张图集 PNG、`preview/` 预览图）；工具 `F:\egg\research\metal_slug_attack\scripts\msa_unit.py`（说明见该目录 README 第 4.4 节）。

### 1.3 斜向转正的原作做法

- MSA 图集中的车体部件为斜置原画。部件脚本以 op2 −285（−25.05°，履带等为 −290）在运行时旋转，同时以 op19 75 缩小到 75%。主槽脚本本身不画帧，以 op11[子脚本, 层级, x, y] 把底盘、履带、车身、主炮、发射架等部件挂在各自位置。
- 旋转后的四边形按最近邻采样绘制到画面分辨率，画面上为倾斜的像素格。R1–R4 以 RotSprite / MMPX 离线旋转并重新落到水平像素网格，锯齿来自这一步。
- 预览（`msa_unit.py preview`）按上述语义执行脚本，拼合结果与受击框吻合，车头朝右（预览图 `preview/slot*_parts75.png`）。

## 3. 重做方案

### 3.1 数据（直接转换，不重绘）

- 图集转为 MSD `OI 01 08`（两张均不超过 256 色，无需重新量化）。
- 描述符：矩形、帧、受击框、攻击框与 142 条脚本由 MSA 记录直接生成；0–23 号指令保持原值；op24 / 26 / 28 删除，op26 的击退关闭由行为在对应状态处理。
- 音效（op23）：脚本引用 12 个 SoundID（204、208、212、229、249、260、261、279、332、457、491、688），MSA 数据中全部存在。与 MSD 原生同号同名者沿用原生 ID，其余以 MSA 的 `.msa`（Ogg）登记为本体音效键。

### 3.2 尺寸（2026-10-21 用户要求：不按 MSA 缩小一号）

- 部件 op19 75 → 100；op11 / op12 / op22 的偏移、op14 位移、部件与弹体脚本内的 op7、受击框与攻击框、行为中的固定坐标（爆炸点、召唤点）按 4/3 缩放。受击框 216×106 → 288×141。
- 未写 op19 的效果层（共用爆炸、炮口火光、烟、火焰）保持 100%，与 MS6 原画的相对比例一致。
- 4/3 后的车体大小与 MS6 原作 1:1 相当，与第 176 节选定的尺寸接近。对照图：`preview/compare_slot*_75_vs_100.png`（左 MSA 原样、右部件 100%）。

### 3.3 旋转

- 沿用 op2 运行时旋转，不做离线旋转。
- 首个实施步骤为实机核对：宿主是否直接以窗口分辨率绘制战斗精灵。若先绘制到低分辨率缓冲再放大，倾斜像素会被重新量化，需要另行处理。

### 3.4 行为（C++ 行为库）

- 新增与 MSA 动作类对应的行为：单位 2 个（第一、第二形态）、弹体 6 个，按 MSA 反汇编逐函数移植，调用 MSD 原生 `BattleObject` 方法。
- 第二形态按 MSA 方式实现：第一形态以状态 125 结束后召唤内部单位（新 UnitID，`internal_only`），替代第 176 节的 `hp_stage_animations` 方案。
- 属性倍率与伤害下限不实施（MSD 无对应属性，延续第 176 节不做屏障的决定）。
- 新增 C++ 行为须检查回滚确定性（N1 驱动）。

### 3.5 数值

- MSA 数值表（`m_unit_level_status_1`–`10`）已导出到研究目录，例：287 与 288 第 1 列 Lv1 100000、Lv20 200000、Lv40 300000、Lv50 350000（进化 1）；第 4 列（287）2000–7000，第 6 列 288 为 16000–56000、287 为 800–2800，第 8 列（287）10000–35000。各列含义实施时逐列核对。
- 两种做法待用户选择：沿用第 176 节数值（AP 800、Lv40 生命 44000，伤害按 MSA 比例缩小），或按 MSA 数值表与第 6.1 节规则重新换算。

### 3.6 旧版与验证

- 沿用稳定键 `s1xlv.iron_sentinel` 与 UnitID 1062；删除 R4 的图集、描述符、脚本与生成脚本输出；完成并验证后从 `disabled_units` 移除。
- 验证：图集与描述符结构检查；逐槽与预览对照；LAB 自然对战（双方阵营）；形态转换与召唤；击退免疫；回滚确定性；动作演示图像范围；按第 2.2、2.3 节同步两个固定运行目录。

## 5. 补充：MSD 1.46 原生的 IRON SLIDER（2026-10-21，方案确认后的核查）

- MSD 1.46 原生库含有 `BattleAction_IronSlider`、`BattleAction_IronSlider_2` 与 6 个弹体类（`Atack_L`、`Atack_SP`、`Atack_S`、`Atack_S_SUB`、`Atack_2`、`Atack_2_SUB`），对应函数均已在重编译核心 `src/generated/` 中（如 `b_101bdaec` 为 `BattleAction_IronSlider::update`）。
- 原生描述符 0x977c4c 的图集名（`iron_slider_out.obm`、`ironiso_1_out.obm`）、318 个矩形与 638 字帧表与 MSA 记录逐项相同；脚本 115 条（MSA 142 条，编号不同），战斗槽的部件偏移相同，受击框为 (−105, −110, 193, 115)。MSD 资源中没有 `iron_slider_out.obm`。
- 原生数据行 UnitID 394 名为 IRON SLIDER（各语言文本齐全），第二形态 395（MSD 版 `summonUnit` 召唤 0x18b = 395）；运行时（r72，隔离存档，`verification/iron_sentinel_msa_20261021/driver_native_ironslider.py`）394 / 395 的动作表项为 `BattleAction_Zako`，描述符为普通兵的 0x97510c；`BattleAction_IronSlider` / `_2` 的虚表位于 393（SlugnoidTypeB）与 396（TruckSlug）之间，描述符 0x977c4c 位于 393 与 396 的描述符之间，即该单位在 MSD 中被替换为占位而未发布。
- MSD 原生 `BattleAction_IronSlider::update` 的状态与动作槽：10→6、20→7、30→8、40→9、50→10、70→11、80→12、100 / 110 / 120→13，与 MSA 7.13 版（30 / 40→9、70→12、80→11）不同，属较早版本。
- 对第 3.4 节的影响：可选用 MSD 原生动作类与弹体类（加载器构造指向其虚表的动作对象），按其槽号重排 MSA 脚本；或按原方案移植 MSA 7.13 版逻辑。两版逻辑的差异（槽号、召唤与第二形态生命、弹体结算）在实施前逐函数比较后再选定，结果报告用户。
- 采用的做法（2026-10-21 实施）：使用 MSD 原生动作类与弹体类，脚本保持 MSA 7.13 编号，以 7 个核心钩子（r73）把槽号、弹体编号、召唤对象、绘制偏移、火箭瞄准与主炮导弹爆炸按 MSA 处理；第二形态由原生 `summonUnit` 召唤内部单位 1063。实现与验证见 `docs/IRON_SENTINEL_2026-10-21.md`。
