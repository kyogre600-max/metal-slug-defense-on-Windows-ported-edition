# PVZ EVENT（游戏内名称 PVZ EVENT；2026-10-15，本体 EVENT，核心 r60 起，现为 r63）

以猫咪大战争 PART1 为出兵与奖励参照的本体自制 EVENT。第 1–8 节为最初的两个大关（当时名称 PVZ 联动(PART1)），第 9 节为第三至第五大关，第 10 节为名称与封面。数据为 `community_content/events/pvz_part1.json`，由
`artwork/pvz_event_part1_20261015/build_event.py` 生成（同时生成两张 128×56 小关缩略图）。

## 1. 用户设定

- 两个大关各 4 个小关；地点为美国东部（第一大关）与美国中部（第二大关），活动地图使用通用 EVENT 世界地图。
- 敌军等级：第一大关 5 / 10 / 15 / 20，第二大关 30 / 40 / 40 / 40。
- 强度系数（关卡强化，每级生命与攻击 +20%）：第一大关无；第二大关 0% / 40% / 60% / 100%。
- 敌军构成：1-1 普通；1-2 加路障；1-3 加铁桶；1-4 加读报；2-1 去掉普通、加橄榄球；2-2 去掉路障、加冰车；2-3 加巨人；
  2-4 只有读报、橄榄球、冰车、巨人。
- 战场：猫咪大战争的场地，第一大关白天草地（场景 116），第二大关黄昏（场景 117）。
- 配乐：全部关卡使用 Watery Graves 合金弹头风格混音（用户提供）。
- 奖励：解救人质（`rescue` 模式）。第一大关各关人质 1 / 1 / 2 / 2，全部救出解锁小鬼僵尸；第二大关 3 / 3 / 5 / 7，全部救出解锁读报僵尸。
- 俘虏为常规关卡的俘虏。

## 3. 实现

### 3.1 自制 EVENT 的出兵控制（宿主，`event_content.py`）

自制 EVENT 的关卡记录此前只写出兵表（词 19/20），词 21–24、28、29 置零，出兵表执行一遍后不再出兵。新增小关字段，写入与历史活动相同的原生字段
（静态核对 `BattleControllerEnemy::update` 0x1ca044、`updateFirst` 0x1c9e7e、`runScriptAction` 0x1c9f6c、`BattleScene::setupResourceAll` 0x1d45f0）：

| 字段 | 关卡记录 | 原生语义 |
| --- | --- | --- |
| `loop` | 词 21/22 第一条 `(0, n, 1, 0, 可重复)` | 出兵计时等于 n 时设回 0 |
| `triggers` | 词 21/22，每条 20 字节（条件、值、动作、参数、可重复） | 条件 0 计时相等、1 敌方据点生命百分比低于、2 我方最前单位（对象管理器 +0x30）与敌方据点距离小于；动作 0 出兵（名单序号）、1 设定出兵计时、2 追加关卡强化级数；以 32 位掩码记录已触发，故每关至多 32 条 |
| `placed` | 词 23/24，每条 4 字节（名单序号 int8、横坐标/2 int16） | 第一帧在该横坐标创建敌方单位 |
| `items`、`item_level`、`prisoner_chance` | 词 28/29（x、离地高度、权重）、词 26、词 27 | 每场随机取约 67% 的位置放置道具（UnitID 116）或俘虏；每处俘虏概率按权重乘 1.4/1.2/1.0/0.9/0.8，每出现一名减半 |
| `difficulty` | 词 9 | 关卡信息窗的难度标签（`GetStageLevel`），0 为 EASY |

俘虏与道具是藏在战场中的隐形对象（`BattleAction_Item` 0x19d9a8）：攻击打中时出现受击火光（效果 0xff15），生命归零后现身（状态 141）
并 `notifyEventGetStageItem`，类型 1 计入本场救出数（`BattleScene::onEventGetStageItem` 0x1d518e）。历史活动“盛夏恐怖夜”的俘虏同样如此。

### 3.2 常规俘虏（核心 r60，`src/event_trial_hooks.cpp`）

`setupResourceAll` 在 WorldType 1（经典活动路由，自制 EVENT 使用）下把俘虏候选对象固定生成为 UnitID 289（巨灵战车零件，0x1d4e32），
其余情形生成常规关卡的俘虏 UnitID 231（0x1d4e76）。新增钩子 `regular_prisoner`（0x1d4e26）：活动头部 +224 非零时改走常规分支；
宿主选择自制 EVENT 时写入（`event_trial.py`），历史活动保持原状。导出 `msd_custom_event_prisoner_version()`。
核心 `MSD_Core_LAB_r60_20261015.dll`（r59 加本钩子）。

### 3.3 配乐与自制 bgm 循环修正

- 用户提供的 m4a（AAC，48 kHz，212 秒）经 Windows 自带 MediaTranscoder 解码，按 3:1 重采样为 16 kHz 立体声（与原版 BGM 相同；本移植版混音输出为 16 kHz），
  以 libsndfile 编码为 Ogg Vorbis，导入为 `community_content/bgm_pvz_watery_graves.msdf`（180.2 秒，1.2 MB）。处理脚本与中间文件在研究目录
  `content_work/pvz_event_part1_20261015/music/`。
- 循环：曲子以 99.918375 秒为周期重复（互相关 0.98）；按两遍波形差异最小处取 179.725 秒 → 79.806625 秒（相对差异 6.8%）。
- 登记：`content.json` 的 `sounds` 新增 `s1xlv.bgm_pvz_watery_graves`（bgm，`loop` [79.806625, 179.725]，`gain` 1.5，使响度与原版 BGM 相近）。
  键不以 `s1xlv.pvz_` 开头，以免 PvZ 单位生成脚本重写音效表时被移除。
- 修正（M6a 起的问题）：原生音效表记录第 12 字节的低 8 位为循环次数（`CMediaSound::CreatePlayerFromFile` 存入 +0xc4，`CAudioPresenter::loopCheck`
  以负值为无限循环），原版 BGM 均为 0xFF；`content_sounds.py` 此前写 `音量 × 256`（低字节 0），自制 bgm 播放到循环终点即停止。现 bgm 条目写入 0xFF。

## 6. 战败流程修正（核心 r61，同日用户反馈）

- 用户反馈：战败后直接黑屏约 1–2 秒即回到地图。原因：宿主在原生接关窗（场景 110 / 120）出现时直接结算战败（历史活动预览阶段的规则，当时认为付费接关依赖隔离档案以外的服务状态），常规关卡的“確認是否繼續”（花 10 勋章，带 APMAX 与金属弹头攻击 MAX 再战）、取消后的“是否要脫離戰鬥”与失败结算画面全部被跳过。
- 修正（`event_trial.py` 及镜像，`EventTrial.NATIVE_CONTINUE = True`）：活动战败沿用原生接关流程；结算仍在原生结束战斗（SC_BattleEnd）时由既有 `event_end` 钩子交给宿主记录。对全部活动生效；合作活动（模式 6）与 Survival 路由（原生无接关窗）行为不变。
- 结算画面的俘虏图标：`BattleResultScene::initialize` 在模式 3 下（一周年除外）以 UnitID 289（零件）作为图标；核心 r61 新增钩子 `regular_prisoner_result`（0x1d18d8），自制 EVENT 时改为常规关卡的类型 0（PRISONER RESCUE 与常规俘虏图标）。`msd_custom_event_prisoner_version()` 为 2。
- 验证（隔离存档，r61，`run_lose.py`）：PVZ 1-1 战败 → 接关窗 → CANCEL → 确认脱离 → 失败结算画面（MISSION FAILED、评级、时间、奖励）→ 点击 → 回到活动地图，进度记录挑战 1 次、胜利 0；接关窗两次 OK → 扣 10 勋章（4252 → 4242）、AP 与金属弹头攻击满后再战 → 取胜 → MISSION COMPLETE（PRISONER RESCUE 常规俘虏图标）→ 回到地图并记录胜利；历史活动盛夏恐怖夜（经典路由）同样经接关与结算回到地图并记录；秘宝（Survival）原生无接关窗，直接结算回地图。猫咪活动（两页地图）未以本驱动测试。回归：本 EVENT 8 关 113 项与重启 2 项、M6b-3 18 项、历史 EVENT 13 入口 156 项。

### 9.5 敌方生命的 10% 加成（更正第 4 节）

- 原因（静态反汇编）：`BattleController::onEventUnitCreate`（0x1c961e）把控制器 +0x3a0 传给 `BattleObjectManager::createUnit`，为真时 `BattleObjectFactory::createUnitStatus`（0x1d1370）在关卡强化之外再加“数据行 +0x37c 的百分比”生命（原版 399 个单位均为 10），即同阵营编队加成。玩家控制器由 `BattleStartSetStatus` 按编队是否同一阵营设定；敌方控制器只在 Wi-Fi 对战中由 `BattleStartSetStatusEnemy` 设定，单人关卡从未写入，而 `BattleControllerEnemy`（`operator new` 分配 0x448 字节）的构造函数也不初始化该字节，其值为堆的残留内容。验证中同一进程第一场为 0，之后的战斗读到 168、76 等非零值，出兵僵尸生命因此时有时无地多 10%（第 4 节当时的记录即此情形）。开门单位经 `updateFirst` 创建，固定不加。
- 处理：`event_native_map.py` 在自制 EVENT 战斗（场景 100）的第一帧把敌方控制器 +0x3a0 写为 0，出兵单位的生命严格为目录生命 × (1 + 0.2 × 强化级数)。历史活动与普通世界关卡未改（原版同样存在此未初始化读取，本移植版中第二场战斗起敌方出兵单位多 10% 生命）。
